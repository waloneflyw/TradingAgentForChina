# A股智研 · 前后端启动与局域网访问操作手册

> 适用环境：Windows 11 本机开发/演示。后端 FastAPI（8000）+ 前端 Vue3/Vite（5173）。
> 本文档只讲「怎么打开」和「怎么让同局域网的人访问」，不含业务开发说明。

## 2. 启动后端（FastAPI，端口 8000）

打开一个终端，执行：

```bash
cd D:\AgentFrame\TradingAgentForChina\backend
C:/Users/24167/.conda/envs/tradingagents/python.exe run_server.py
```

- 默认监听 **`0.0.0.0:8000`**（已对局域网开放，无需改配置）。
- 换端口：`... run_server.py --port 8080`（换端口后前端代理目标也要跟着改）。
- 启动成功的标志：日志出现 `Uvicorn running on http://0.0.0.0:8000`。
- 自检：浏览器打开 `http://127.0.0.1:8000/api/health`，返回 JSON 即正常。

> 注意：`run_server.py` 启动的是 `app.api.main:app`，若后端有 Python 改动需重启进程才能生效。

## 3. 启动前端（Vite，端口 5173）

另开一个终端，执行：

```bash
cd D:\AgentFrame\TradingAgentForChina\frontend
npm run dev
```

- 已在 `vite.config.ts` 里加了 `host: true`，所以 `npm run dev` 会自动监听 `0.0.0.0:5173`，局域网可直接访问。
- 前端所有 `/api` 请求由 Vite 代理转发到本机 `127.0.0.1:8000`（代理跑在服务器本机，局域网客户端无需直连后端）。
- 启动成功的标志：日志出现 `Local: http://localhost:5173/` 和 `Network: http://<本机IP>:5173/`。

## 5. 让同局域网的人访问

### 5.1 查本机局域网 IP

在本机（跑服务的那台）执行：

```powershell
ipconfig
```

找到当前网卡的 **IPv4 地址**（形如 `192.168.x.x`），记为 `<本机IP>`。

> 当前这台机器的局域网 IP 是 **`192.168.3.17`**（网卡「以太网」，实测于 2026-09-16）。

### 5.2 局域网其他人访问

让同事在浏览器打开：

```
http://<本机IP>:5173
```

例如本机 IP 是 `192.168.3.17`，就访问 `http://192.168.3.17:5173`。

### 5.3 防火墙放行（关键，多数访问失败都是这里）

Windows 默认会拦截入站连接，需要放行 **5173** 和 **8000** 两个端口。以管理员身份打开 PowerShell：

```powershell
# 放行前端 5173
New-NetFirewallRule -DisplayName "A股智研-前端5173" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5173
# 放行后端 8000
New-NetFirewallRule -DisplayName "A股智研-后端8000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000
```

> 说明：因为前端把 `/api` 代理到后端，局域网客户端实际上只需访问 **5173** 即可；放行 8000 是为了「直连后端自检 / 未来去代理」时也能通，二选一都行，建议两个都放。

## 6. 两种运行模式对比

| 模式 | 命令 | 端口 | 适用场景 |
|---|---|---|---|
| 开发模式（推荐演示用） | `npm run dev` | 5173 | 改前端即时热更新，方便现场调试 |
| 构建预览（更接近生产） | `npm run build` 然后 `npm run preview` | 4173 | 构建产物访问，性能更好、更稳定 |

`npm run preview` 同样已配 `host: true` 和 `/api` 代理，局域网访问 `http://<本机IP>:4173` 即可。

## 7. 常见问题（FAQ）

**Q1：局域网同事打不开，本机能打开？**
答：99% 是 Windows 防火墙拦截。按 5.3 放行端口，或临时关闭防火墙验证。

**Q2：页面能打开，但发消息/分析一直转圈？**
答：后端没起来或代理不通。检查：① 后端终端是否 `Uvicorn running`；② 后端是否还在跑（8000 被占用会启动失败）；③ `curl http://<本机IP>:8000/api/health` 是否通。

**Q3：提示连接 MySQL 失败？**
答：确认本机 MySQL 服务已启动（`services.msc` 里找 MySQL），`.env` 里连接信息正确。

**Q4：分析慢/无数据？**
答：可能是数据回填任务（财务全市场回填）还没跑完，或东财源限流。属数据侧问题，与前后端启动无关。

**Q5：换端口后前端连不上？**
答：改了后端 `--port` 后，需同步改 `frontend/vite.config.ts` 里 `/api` 的 `target` 端口，再重启前端。

**Q6：部署到新服务器还需要 `fastapi_db` 吗？**
答：**不需要。** 后端运行时（`run_server.py`）只连接业务库 `ashare_agent`，`fastapi_db` 只在一次性迁移脚本（`scripts/migrate/*`、`scripts/pipeline/stock_info_fill.py`）里用到，不参与运行。新服务器上只需有 `ashare_agent`（及其数据）即可。数据建议直接从本机 `mysqldump` 导出 `ashare_agent` 再在新服务器导入，而非重新迁移。

## 8. ⚠️ 安全提醒

- **当前 MVP 没有登录鉴权**，所有数据挂在内置 demo 用户下。
- **只能在受信任的局域网内开放**，切勿映射到公网 / 关闭防火墙对外暴露。
- `.env` 含 MySQL 密码与 DeepSeek API Key，**不要拷贝给他人、不要提交到 git、不要写进聊天/文档**。
- 正式对公网开放前，必须先完成登录鉴权（阶段 5 后续）。
