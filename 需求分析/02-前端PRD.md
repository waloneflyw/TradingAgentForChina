# 02 · 前端 PRD（产品需求文档 v0.1）

> 状态：**讨论稿**，与 [01-整体实现思路.md](01-整体实现思路.md) 配套。带 ❓ 的是待用户拍板项。
> 范围：MVP 前端（金融助手聊天 + 个股深度分析 + 标签选股），不含交易、回测、组合监控。
> 技术栈定案（见 01 §2）：Vue3 + ECharts + 自绘 SVG 流程图 + SSE。

## 0. 一句话产品定义

一个**以金融助手聊天框为中心**的 A股分析工作台：用户通过对话或按钮，触发「个股深度分析 / 标签选股」，整个过程以「调用同事」的形式实时展示在聊天框里，最终沉淀为一份带评级、带数据来源、带免责声明的分析报告。

## 1. 设计原则（5 条）

1. **聊天框是唯一入口**。不搞多页面跳转，所有能力（个股分析/选股/日常问答）都在聊天流里发生、回流。
2. **过程透明优先**。SSE 是硬要求——用户必须能实时看到「哪个 agent 在干嘛、调了什么数据、数据从哪来」，这是本产品区别于普通炒股 App 的核心卖点。
3. ✅ **三层可视化 = 三 Tab，不是同屏三栏**。结论 / 过程 / 依据三种视图，用 Tab 切换；手机窄屏也能用，桌面宽屏也清爽。
4. **红涨绿跌（A股惯例）**。所有涨跌配色红=涨、绿=跌，与美股配色相反，写死在主题 token 里。
5. **合规无处不在**。免责声明在「聊天框底部 + 报告卡片尾部 + 评级旁」三处常驻，不是一次性弹窗。

## 2. 信息架构 / 页面地图

```
主应用（单页 SPA）
├── 主布局：会话侧栏 + 聊天区
│   ├── 会话侧栏（历史会话列表 / 新建会话）
│   └── 聊天区
│       ├── 消息流（用户消息 / 助手消息 / 任务卡片 / 报告卡片）
│       └── 输入区（文字 + 「个股深度分析」「标签选股」按钮 + 快捷指令）
│
├── 个股分析工作台（从报告卡片展开，全屏）
│   ├── Tab1 结论：评级 + 各分析师报告 + K线/指标图
│   ├── Tab2 过程：agent 流程图（SVG，11 节点）
│   └── Tab3 依据：时间线（工具调用 + LLM 输出 + 数据来源）
│
├── 选股工作台（从任务卡片展开，全屏）
│   ├── 标签面板（行业/板块/估值/技术/风险 多选）
│   ├── 候选池表格（虚拟滚动）
│   └── 追问条（增量加标签，二次筛选）
│
└── 历史报告页（侧栏入口，报告列表 + 详情）
```

## 3. 主布局规格

### 3.1 会话侧栏（左）
- 折叠/展开，窄屏默认折叠。
- 列表项：会话标题（取首条消息或自动摘要）+ 最近时间 + 未读标记。
- 顶部「+ 新建会话」。
- 底部「历史报告」入口 → 跳历史报告页。

### 3.2 聊天区（中，核心）
- 消息类型（5 种）：
  1. **用户消息**：右对齐气泡。
  2. **助手消息**：左对齐，Markdown 渲染（支持表格/加粗/列表）。
  3. **任务卡片**（TaskCard）：用户触发分析/选股后插入，实时滚动「调用同事」进度（见 §4.1）。
  4. **报告卡片**（ReportCard）：任务完成后替换/附着任务卡片，显示评级摘要 + 「展开工作台」按钮（见 §4.2）。
  5. **系统消息**：合规提示、错误、任务失败等，灰色小字。
- 消息流支持**滚动到最新** + **回看历史**（分页加载，见 01 记忆与持久化）。
- 底部固定**免责声明条**：「本服务由 AI 自动生成，仅供信息参考，不构成投资建议；股市有风险，入市需谨慎」。

### 3.3 输入区
- 文字输入框（多行，Enter 发送 / Shift+Enter 换行）。
- 左侧两个主按钮：
  - **「个股深度分析」**：点击弹出股票搜索框（代码/名称/拼音联想，`search_stock`）→ 选股后触发分析。
  - **「标签选股」**：点击弹出标签面板 → 选标签后触发初筛。
- 快捷指令条（可配置）：`/分析 600519`、`/选股`、`/大盘`、`/报告`。

## 4. 核心组件规格

### 4.1 TaskCard（任务卡片 /「调用同事」进度卡）
- 触发时机：用户点按钮或对话路由后，立即插入。
- 内容：任务标题（"正在分析：贵州茅台 600519.SH"）+ 实时进度区。
- 进度区 = **迷你流水线**（agent 名单 + 状态点）：
  - 每个 agent 一行：图标 + 名称（市场分析师/基本面分析师/新闻分析师/社媒分析师/牛熊研究员/…）+ 状态（等待/运行中/完成/失败）+ 耗时 + token。
  - 运行中的 agent 有脉冲动画。
- 数据来源：SSE `node_start` / `node_end` 事件驱动（见 §6）。
- 完成后整卡自动替换为 ReportCard。

### 4.2 ReportCard（报告卡片）
- 顶部：**五档评级徽章**（买/增持/持有/减持/卖，色阶：买=深红、增持=红、持有=灰、减持=绿、卖=深绿）+ 股票名 + 代码 + 分析时间。
- 摘要：一段结论摘要（LLM 生成，可折叠）。
- 按钮：「展开工作台」→ 打开个股分析工作台。
- 尾部：免责声明 + 数据来源徽章（QMT/akshare/MySQL 各数据用了哪个）。

### 4.3 RatingBadge（五档评级徽章）
- 五档色阶（红涨绿跌）：
  | 评级 | 颜色 | 含义 |
  |---|---|---|
  | 买 | 深红 `#d32f2f` | 强烈看多 |
  | 增持 | 红 `#f56c6c` | 偏多 |
  | 持有 | 灰 `#909399` | 中性 |
  | 减持 | 绿 `#67c23a` | 偏空 |
  | 卖 | 深绿 `#2e7d32` | 强烈看空 |
- 措辞弱化（合规层 ③）：徽章旁加"相对"前缀，如「相对偏多」，hover 提示"不构成投资建议"。

### 4.4 AgentPipeline（流程图，SVG 自绘）
- 11 节点，4 阶段布局（参考 01 编排层）：
  - 阶段一：4 分析师（市场/基本面/新闻/社媒）并行
  - 阶段二：牛熊研究员辩论
  - 阶段三：研究经理汇总
  - 阶段四：交易员 → 风控三方辩论 → 组合经理
- 节点状态：等待（灰）/ 运行（蓝，脉冲）/ 完成（绿，✓）/ 失败（红，✗）。
- 节点上标耗时 + token。
- 点击节点 → 打开「依据层」面板（该节点的工具调用明细）。
- ✅ 已定：**自绘 SVG**。11 节点是固定结构，用不上 AntV X6 的拖拽/连线编辑能力；自绘 SVG 可控性更强、依赖更轻、和 SSE 状态联动更直接。

### 4.5 EvidencePanel（依据层时间线）
- 纵向时间线，每步一条：
  - 步骤类型：工具调用 / LLM 输出 / 消息清理 / 节点进出。
  - 工具调用项：`工具名` + `入参摘要` + `返回摘要` + **数据来源徽章**（QMT/akshare/MySQL）+ 行数。
  - LLM 输出项：可折叠的完整文本。
- 目的：回答「这个结论是怎么来的」，数据来源徽章是硬要求（01 §12 依据层核心）。

### 4.6 KLineChart / IndicatorChart（K线 + 指标）
- ECharts `candlestick` + MA5/10/20/60 均线叠加。
- 下方子图：MACD / RSI / BOLL / KDJ，可切换。
- 时间范围：日K / 周K / 月K，及区间选择（近1月/3月/6月/1年/3年）。
- 复权切换：前复权（默认）/ 后复权 / 不复权。
- 红涨绿跌：阳线红、阴线绿，全站统一。
- 数据：复用后端 `get_stock_data`（查库 → 缺则 QMT/akshare 拉取落库）。

### 4.7 ScreenerForm（选股标签面板）
- 标签分组（对应 01 §8 两层漏斗的量化初筛因子）：
  | 组 | 标签示例 |
  |---|---|
  | 行业 | 申万一级/二级（医药/新能源/半导体/…） |
  | 板块 | 概念板块（AI/机器人/高股息/…） |
  | 估值 | PE<30、PB<2、股息率>3% |
  | 成长 | 营收增速>20%、净利增速>20%、ROE>15% |
  | 技术 | 突破年线、MACD 金叉、放量 |
  | 风险 | 剔除 ST、剔除亏损、剔除次新 |
- 多选 + 组合（组内 OR、组间 AND），提交前实时预览"预计命中 N 只"（可选，成本高则后补）。
- 提交 → 量化初筛（纯 SQL，`get_stock_screener`）→ 结果表格。

### 4.8 StockTable（候选池表格，虚拟滚动）
- 全市场 5000+ 候选，**必须虚拟滚动**（01 §5 阶段 5 已列）。
- 列：代码/名称/行业/现价/涨跌幅/PE/PB/ROE/命中标签数。
- 行点击 → 展开该股摘要，或「去分析」→ 触发个股分析。
- 排序：按命中标签数 / 涨跌幅 / PE 等列排序。
- 顶部「追问条」：`+ 追加标签` 输入框，增量筛选（追问闭环，MVP 必做）。

## 5. 个股分析工作台（三层可视化落地）

从 ReportCard 或 TaskCard 展开的全屏视图，三 Tab：

```
┌────────────────────────────────────────────────────────────┐
│ 贵州茅台 600519.SH   [评级徽章]   分析时间   [关闭]         │
├────────────────────────────────────────────────────────────┤
│ [结论] [过程] [依据]   ← Tab 切换（分析中默认停「过程」）     │
├────────────────────────────────────────────────────────────┤
│  Tab 内容区                                                │
└────────────────────────────────────────────────────────────┘
```

- **Tab1 结论**：五档评级大字 + 评级理由 + 各分析师报告（市场/基本面/新闻/社媒/牛熊辩论，各自可折叠）+ K线/指标图 + 免责声明。
- **Tab2 过程**：AgentPipeline 流程图（§4.4），实时状态。
- **Tab3 依据**：EvidencePanel 时间线（§4.5），按节点分组。

**Tab 联动逻辑**：
- 分析进行中：默认停在「过程」，用户看 agent 跑。
- 全部节点完成：自动切「结论」，展示报告；用户仍可切回「过程/依据」回看。
- 任意 Tab 点某节点/某结论 → 跳「依据」对应位置。

## 6. SSE 实时交互规格

### 6.1 事件类型 → UI 映射

| SSE 事件 | 字段 | UI 动作 |
|---|---|---|
| `task_created` | task_id, type(analysis/screener) | 插入 TaskCard |
| `node_start` | node_name, agent | 流程图节点 → 运行中；TaskCard 对应行 → 运行中 |
| `node_end` | node_name, elapsed, tokens | 节点 → 完成 + 标耗时/token |
| `llm_token` | node_name, delta | 流式追加到助手消息/该节点 LLM 输出 |
| `tool_call` | node_name, tool, args | 依据层新增"工具调用"行 |
| `tool_result` | node_name, tool, summary, source | 补全返回摘要 + **数据来源徽章** |
| `report` | agent, markdown | 报告卡片追加该 agent 报告段落 |
| `done` | report_id, rating | TaskCard → ReportCard，工作台切「结论」Tab |
| `error` | node_name, message | 节点 → 失败；系统消息提示 |

### 6.2 订阅与断线
- 订阅 `/api/analysis/{task_id}/stream`（01 §2.5 每 task 一个 asyncio.Queue）。
- **断线重连**：SSE 重连后后端回放未消费的结构化摘要（落 `analysis_trace` 的那部分）；即时流（llm_token）不回放。
- **回看**：历史报告页从 `analysis_trace` 完整重建「过程/依据」两 Tab（不依赖实时流）。

## 7. 关键交互流程

### 7.1 个股深度分析
1. 用户点「个股深度分析」按钮（或对话说"分析贵州茅台"）。
2. 弹出股票搜索框 → `search_stock` 模糊搜 → 用户选股。
3. 前端 `POST /analysis` → 拿 task_id → 订阅 SSE。
4. 聊天流插入 TaskCard，实时滚动「调用同事」进度。
5. 完成 → TaskCard 变 ReportCard（评级摘要）。
6. 用户点「展开工作台」→ 看结论/过程/依据三层。

### 7.2 标签选股（含追问闭环）
1. 用户点「标签选股」按钮。
2. 标签面板多选 → 提交。
3. `run_screener` → 量化初筛（SQL）→ 候选池表格（虚拟滚动）。
4. **追问闭环**：用户在「追问条」追加标签（"只看新能源、PE<30"）→ 增量筛选 → 表格刷新。
5. 用户点某只股「去分析」→ 跳到个股分析流程（7.1 第 3 步起）。
6. ~~可选：对候选池做 LLM 精析（两层漏斗第二阶段）~~ ⏸️ **MVP 后补**：MVP 只出量化初筛列表，用户点股跳分析；LLM 精析第二阶段留到后补。

## 9. 主题与视觉

- ✅ 已定：**三态主题**——默认「跟随系统」，可手动切「暗色 / 亮色」；涨跌色（红涨绿跌）三态下保持一致。
- 实现：色板用 CSS 变量（token），`data-theme` 挂根节点（light/dark），跟随系统靠 `prefers-color-scheme`；暗色值如下，亮色值开工时补。
- 色板 token（暗色）：
  - 涨红 `#f56c6c` / 深红 `#d32f2f`；跌绿 `#67c23a` / 深绿 `#2e7d32`。
  - 背景深 `#0f1419`，卡片 `#1a2129`，边框 `#2a3340`，主文字 `#e6edf3`。
  - 节点状态色：等待 `#3a4554` / 运行 `#3b82f6` / 完成 `#22c55e` / 失败 `#ef4444`。
- 字体：系统栈 + 等宽字体（数字/代码）。
- 响应式：桌面两栏（侧栏+聊天），窄屏单栏（侧栏抽屉化）。

## 11. 与后端的接口约定（对齐 01）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/analysis` | POST | 触发个股分析，返回 task_id |
| `/api/analysis/{task_id}/stream` | GET(SSE) | 订阅分析过程 |
| `/api/screener` | POST | 量化初筛，返回候选池 |
| `/api/conversations` | GET/POST | 会话列表 / 新建 |
| `/api/conversations/{id}/messages` | GET | 历史消息分页 |
| `/api/reports` | GET | 历史报告列表 |
| `/api/reports/{id}` | GET | 报告详情（含 trace 重建） |
| `/api/stocks/search` | GET | 股票搜索联想（search_stock） |
| `/api/market/overview` | GET | 大盘概览（get_market_overview） |

> 数据来源标注（QMT/akshare/MySQL）由后端在 `tool_result` 事件里带 `source` 字段，前端只负责渲染徽章，不自行判断来源。
